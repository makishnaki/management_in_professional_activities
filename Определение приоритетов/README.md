**Тема:** Выполнение фрагмента SWOT-анализа для IT-проектов

## Ситуация 1.

### Swot:
* **Strengths** - опытные разработчики в команде, собственный дизайнер, небольшая команда
* **Weaknesses** – нет специалиста по маркетингу, риск перегрузки разработчиков
* **Opportunities** - интерес аудитории, потенциал уникального продукта
* **Threats** - активность конкурентов в рекламе, низкая узнаваемость приложения

### короткий управленческий вывод
Команде следует опираться на свою сильную техническую и дизайнерскую экспертизу, чтобы быстро выпустить функции и выиграть за счёт качества продукта, при этом срочно закрыть вопрос с маркетингом.

### приоритет действий менеджера
**Высокий приоритет:**
* Найти маркетолога
* Выпустить 1–2 самые ожидаемые пользователями функции

**Средний приоритет:**
* Провести анализ рекламных кампаний и функционала конкурентов
* Настроить сбор обратной связи от пользователей

### конкретные меры по минимизации угроз и закрытию слабых сторон
**Для устранения слабых сторон:**
* Нанять маркетолога
* Внедрить систему приоритизации задач

**Для минимизации угроз:**
* Запустить программу или акцию для базы пользователей
* Анонсировать обновления в соц сетях

## Ситуация 5.

### Swot:
* **Strengths** - сильные графические дизайнеры и разработчики, применение Agile, достаточный размер команды
* **Weaknesses** - отсутствие опыта работы с микроплатежами, недостаток опыта в игровой экономике
* **Opportunities** - использование готовых платежных систем, привлечение специалиста по гейм дизайну
* **Threats** – появление конкурентов, потеря репутации, риск не пройти модерацию из за правил платежных систем

### короткий управленческий вывод
Нужно использовать качественный движок, графику и гибкость Agile, чтобы быстрее вывести на рынок технологически привлекательный продукт и обойти новых конкурентов и закрыть пробел в работе с микроплатежами через готовые платёжные решения и внешнюю экспертизу, чтобы избежать проблем при релизе

### приоритет действий менеджера
**Высокий приоритет:**
* Выбрать готовую платежную систему
* Привлечь человека с опытом игровой монетизации

**Средний приоритет:**
* Изучить модели монетизации
* Подготовить идеи для маркетинга

### конкретные меры по минимизации угроз и закрытию слабых сторон
**Для устранения слабых сторон:**
* Не писать платёжную систему с нуля
* Научить разработчиков работе с новыми функциями

**Для минимизации угроз:**
* Выпустить продукт с базовой монетизацией
* Провести бета тестирование

## Ситуация 6.

### Swot:
* **Strengths** - чёткое распределение задач, прозрачность прогресса, средний размер команды
* **Weaknesses** - проблемы с коммуникацией, асинхронный формат общения, риск выгорания команды
* **Opportunities** - использование современных инструментов для удалённой работы
* **Threats** – увеличение рамок проекта, срыв сроков, снижение качества продукта

### короткий управленческий вывод
Нужно опираться на уже налаженные процессы контроля и чёткое распределение ролей, чтобы держать проект в рамках графика, но перестроить формат удалённого общения, не допускать новых внезапных расширений функционала в ущерб срокам

### приоритет действий менеджера
**Высокий приоритет:**
* Провести переговоры с заказчиком
* Ввести правила удаленного общения

**Средний приоритет:**
* Провести ревизию текущих задач и найти в них слабые места
* Настроить автоматические уведомления в системе контроля задач

### конкретные меры по минимизации угроз и закрытию слабых сторон
**Для устранения слабых сторон:**
* Внедрить обязательные ежедневные стендапы
* Создать единую базу проекта

**Для минимизации угроз:**
* Формализировать процедуру изменений
* Усилить контроль ключевых точек проекта
